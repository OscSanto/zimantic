# Phase 06 — Kolibri provider

Status: proposed.

## Goal

Search and serve a local Kolibri installation, with each **channel as one
collection** and its searchable subtrees as sources. Read Kolibri's local
database and storage directly; do not require Kolibri to be running. Existing
caption tracks are indexed only when `captions = "index"`; OCR and
speech-to-text are separate opt-ins and are never generated by default.

## Locked model

- **Channel = collection.**
- **Source = searchable unit and content root inside the channel.** By default,
  a source is a top-level topic subtree. If a channel has no usable topics, it
  gets one source covering the whole channel.
- **Item = content node with local files** (video, audio, document, PDF, HTML5
  app, etc.), or an exercise with a permitted public description. Topic nodes
  are grouping, not result rows.
- `granularity` is not exposed per file. Per-node sources are not supported.

## Current state

There is no Kolibri code today. This provider builds on phases 00, 03, 04, and
05: it reuses the phase-00 `[[collections]]` parser and normalized configuration
seam, then supplies discovery metadata, a `ContentStore`, and an
`EntryProducer`.

The initial supported target is **Kolibri v0.19.5**. Pin the v0.19.5 release
and its installed SQLite schema in release-derived fixtures; do not claim support
for older versions until each has its own tested fixture and schema mapping.
The installed channel metadata and device-local availability live in Kolibri's
main database, not in the per-channel databases used for importing/exporting
content. Upstream's [channel importer](https://github.com/learningequality/kolibri/blob/v0.19.5/kolibri/core/content/utils/channel_import.py)
imports into the default database and adjusts availability; the
[default SQLite path](https://github.com/learningequality/kolibri/blob/v0.19.5/kolibri/deployment/default/sqlite_db_names.py)
is `KOLIBRI_HOME/db.sqlite3`.

## Configuration

```toml
[[collections]]
type = "kolibri"
name = "kolibri"                  # unique collection namespace
path = "/library/kolibri"         # Kolibri home: db.sqlite3 + content/storage
label = "Kolibri"
granularity = "children"         # top-level topics; "collection" = whole channel
max_sources = 64
max_entries = 500000
# Private database snapshots; all limits must be positive.
max_snapshot_bytes = 1073741824
snapshot_disk_budget_bytes = 3221225472
snapshot_timeout_seconds = 10
# Bounded HTML5 zip serving; all limits must be positive.
max_html5_zip_entries = 10000
max_html5_zip_directory_bytes = 8388608
max_html5_zip_member_bytes = 268435456
max_html5_zip_total_bytes = 1073741824
html5_zip_timeout_seconds = 10

# After discovering the exact key via `/sources` (or `sources --json` in phase 08):
# [[collections.sources]]
# key = "<exact-discovered-source-key>"
# captions = "index"
# ocr = "tesseract"
# asr = "whisper"
```

Optional overrides when the installation is non-standard:

```toml
database_path = "/library/kolibri/db.sqlite3"
storage = "/library/kolibri/content/storage"
```

Use the phase-00 `[[collections]]` parser; this provider contributes validation for
its own keys and does not add a private TOML parser.

Rules:

- The installed SQLite database is opened read-only; never write, migrate,
  vacuum, or checkpoint it or create/modify SQLite sidecars in the
  installation. SQLite `mode=ro` and `query_only` alone do not guarantee this
  for a live WAL. Use a demonstrably read-only VFS/filesystem or a consistent
  private snapshot that includes committed WAL data; fail closed when no safe
  backend is available. Do not use `immutable=1` on a live DB and silently
  ignore WAL.
- Create private snapshots outside the Kolibri installation and storage roots,
  using a proven SQLite-consistent mechanism that incorporates committed WAL
  data. An online SQLite backup copies the logical database, not the source
  SHM file. One entry-level discovery batch owns and shares the successful
  snapshot across all of that installation's channel runtimes, including
  content requests; it is deleted after the batch and its last readers retire.
  A build may use the pinned snapshot for its initial view but must validate
  against a fresh consistent snapshot before publication.
- Each snapshot, including private SQLite sidecars and temporary files, is
  capped by `max_snapshot_bytes` (default 1 GiB). Retained and in-progress
  snapshots for one configured installation in one process share
  `snapshot_disk_budget_bytes` (default 3 GiB), which must be at least
  `max_snapshot_bytes`. Allow at most two snapshot creations concurrently per
  process. Each attempt, including an optional single retry after a detected
  schema change, has a total `snapshot_timeout_seconds` budget (default 10).
  Enforce limits during creation; never evict a snapshot with active readers.
  Separate processes enforce their own budgets.
- Failed attempts release their temporary snapshots. On initial failure, report
  the configured entry unavailable; on refresh failure, retain the last
  complete published batch and expose an entry-level diagnostic as specified in
  phase 00. A failed fresh build-validation snapshot prevents publication.
  Retry discovery on the next reload; never prune the retained batch's indexes
  merely because refresh failed.
- The main database may contain unrelated user and activity data. Keep any
  private snapshot in an owner-only directory with owner-only files, query
  only the allowlisted content and migration tables, and never expose, log,
  index, or network-transfer unrelated rows. Create a lifetime lease before
  writing a snapshot and hold it shared while its creator or readers use it.
  Cleanup may remove only recognized owned stale snapshots after acquiring the
  lease exclusively; an absent or uncertain lease is not proof of staleness.
  Never delete another process's active snapshot.
- Prove the snapshot backend before implementing the query layer. The supported
  baseline must cover a closed WAL-mode database with no sidecars and a live
  WAL with committed data and existing sidecars, using installed databases from
  the pinned release. Test read-only or missing sidecars separately; unsupported
  cases/platforms fail closed. A blanket unavailable result is not sufficient
  to ship the provider. A private backup destination does not make its source
  connection sidecar-free: SQLite can reuse writable SHM mappings within one
  process, and a closed WAL database with no sidecars may not open with
  `mode=ro` at all.
- A candidate live-WAL backend is a freshly exec'd helper process with
  filesystem write denial for the resolved source database and its sidecars,
  including overridden paths, and no inherited writable source handles or
  mappings. Apply restrictions before opening the source, then use SQLite's
  online backup into the private directory. Prove that the actual platform
  sandbox and SQLite build prevent source and sidecar writes; ordinary
  `mode=ro` alone is not that proof. Use bounded backup steps and terminate
  and reap the helper on timeout.
- A candidate for the closed, sidecar-free case on Linux is a read lease on an
  `O_RDONLY` main-database descriptor, held by a separately supervised
  guardian. With the lease held, verify there is no WAL, SHM, or rollback
  journal and copy the main file to the private directory; check the same
  source identity and lease state before accepting the copy. Open SQLite only
  on the private copy. If a writer attempts to open the source, the guardian
  releases the lease immediately and the copy is discarded, without waiting
  for the copy worker. A deadline also releases the lease and terminates the
  attempt. Lease support, owner permissions, source-path replacement, writer
  races, and prompt release must all be proven; otherwise fail closed. Never
  chmod source files to simulate read-only access.
- Brief writer waits caused by SQLite read locks or the closed-database lease
  are permitted, but no lock may be held for the lifetime of a runtime or
  content request. Cap writer delay at 250 ms per attempt under normal
  scheduling; supervise lock holders independently of disk I/O, abort on a
  lease-break request, and test the bound. Document that a stalled kernel or
  filesystem cannot provide a hard real-time guarantee. Record supported
  platform/filesystem assumptions rather than weakening the no-write rule.
- `path`/`database_path`/`storage` must be local. No network access.
- These configured paths may be absolute and may be retained as private
  runtime/catalog locators. They must not be used as collection/source keys or
  exposed in API payloads, errors, redirects, or logs above debug level.
- `database_path` defaults to `<path>/db.sqlite3` and `storage` defaults to
  `<path>/content/storage`. Set explicit overrides for a non-default active
  database or content directory. The initial provider supports SQLite
  installations only; if `options.ini` explicitly declares PostgreSQL, report
  it unsupported rather than treating an old SQLite file as the live database.
  Another process's environment overrides cannot be inferred reliably:
  document that operators must point to the active SQLite database and storage.
- A missing/unsupported main database or storage directory disables the entry
  with a clear error and does not crash startup; invalid metadata for one
  identifiable channel affects that channel, not other channels.
- Multiple Kolibri installations are allowed via multiple `[[collections]]` entries
  with distinct `name` values.
- `path` and absolute database/storage paths never appear in API payloads.

## Discovery

Create `zimantic/providers/kolibri/`:

```
provider.py
discovery.py       # database queries -> collections/sources
schema.py          # version detection and table/column mapping
entries.py         # nodes -> EntryRecord
store.py           # node/files -> content
captions.py        # discover provider-side caption files; parsing is shared
```

### Database access

- Discover installed channels from `content_channelmetadata` in the main
  SQLite database, using its root/node and file mappings from the same
  consistent snapshot. `content/databases/<channel_id>.sqlite3` files are
  channel import/export artifacts, not the authoritative installed state;
  do not require or fall back to them. Kolibri's
  [path implementation](https://github.com/learningequality/kolibri/blob/v0.19.5/kolibri/core/content/utils/paths.py)
  documents those separate files and the checksum-addressed storage layout.
- Detect the installed schema before content queries. Django's
  `django_migrations` and the required table/column layout identify the tested
  installed schema; do not mistake the exported channel schema version or
  SQLite `user_version` alone for the installed Kolibri version. Pin the
  v0.19.5 content migrations and required layout in release-derived fixtures.
  Keep table/column names and allowlisted migrations in `schema.py`.
- If the schema is unsupported, expose the collection as unavailable with an
  error such as "unsupported Kolibri installation database schema" when a
  channel identity is known, or an entry-level diagnostic otherwise; do not
  guess.
- Queries must be bounded and indexed by channel/parent. Never `SELECT *` from
  the whole node table into memory. Page installed channel rows deterministically
  and verify that root nodes, descendants, and files belong to the same channel.
- Distinct node IDs may share a content ID; preserve each node's context and
  source membership. Orphaned files can be skipped with a debug log.
- Never hold a write transaction or a long-lived read lock. Bound temporary
  writer delays and snapshot attempts as specified above.

The expected installed content tables are `content_channelmetadata`,
`content_contentnode`, `content_file`, and `content_localfile`. Confirm names,
columns, availability/visibility flags, schema-version detection, and storage
mapping against each supported release's migrated main database; record tested
versions and use release-derived installed fixtures with device-local
availability. Do not claim support based only on an export DB or a
hand-invented fixture.

### Collection and source mapping

- Collection key: `kolibri:<name>:<channel_id>`. The channel ID is required
  because one configured installation expands into one collection per
  channel; keys must not collide in runtime maps or index paths.
- One collection per installed channel metadata row.
- Sources:
  - `granularity = "children"` (default): each top-level topic node under the channel
    root becomes a source; leaf nodes directly under the root form one
    "Ungrouped" source. If there are no usable topics, use one whole-channel
    `:root` source instead.
  - `granularity = "collection"`: one source for the whole channel.
  - Other values are rejected rather than silently changing source identity.
- Source keys use `kolibri:<name>:<channel_id>:node:<node_id>` for topics,
  `:ungrouped` for direct leaf nodes, and `:root` for the whole channel.
  An automatic cap collapse uses the distinct `:collapsed` key so an override
  for `:root` cannot silently opt in the collapsed source.
  Validate or safely encode channel/node IDs as URL-safe components and detect
  collisions. Synthetic keys cannot collide with real node IDs.
- Source label: topic title. Source title may include the channel title for
  disambiguation.
- Source `homepage`: the topic node's first browsable child, or `None`.
- `key` = source key; paths inside it address only nodes/files belonging
  to that source.
- Caps:
  - if sources exceed `max_sources`, collapse to one source covering the whole
    channel and log the collapse;
  - if nodes exceed `max_entries`, index up to the cap and mark
    `truncated: true`; serving still works for all nodes.
- Collapse or recovery changes the source keys; report the change and rebuild
  the new sources. Never transfer an enrichment opt-in implicitly to the
  collapsed source. A scan that hits its separate traversal/time budget before
  proving truncation fails explicitly and retains the last published index.
- `available` = the installed database snapshot and storage are readable and
  the source can be queried (runtime-only and never persisted). An empty
  source is available; missing individual files affect those items, not the
  source as a whole. `searchable` = a usable, not
  detectably stale index exists.
- `document_count` = local indexable document/exercise-node count only when
  known without an unbounded count; otherwise `None`.
- `media_count` = local media-item count only when known; otherwise `None`.
- `item_count` = total permitted local content-node items only when known; it
  is never the bounded manifest length.
- `indexed_count` = nodes actually present in the index; `truncated` is true
  when the source exceeds `max_entries`, and the reduced search coverage is
  reported in health/API metadata.
- `body_truncated_count` follows the phase-04 body-coverage contract.
- `media_types` = content families from bounded node/file metadata and storage
  mapping (`text`, `video`, `audio`, `image`, `other`), independent of whether
  the node is indexed or derived text is enabled. Use `None` only when no
  usable family was observed; otherwise list every observed family, including
  from a partial or truncated classification. Use `()` only after complete
  classification finds no supported families; rescan that result once and warn
  if it remains empty. A specific content-type filter matches only a non-null
  value containing the requested family; the unfiltered "All" view still
  includes both `None` and empty values.

### Channel and source icons

- Use only the pinned release's validated local thumbnail encoding or
  DB-mapped storage file, bounded by the icon byte limit. Do not fetch a URL
  from channel metadata. Return `None` for unsupported/missing thumbnails
  rather than generating or crawling an icon.

## Indexing

`KolibriEntryProducer`:

- Enumerates **leaf content nodes with at least one locally available file**.
  Topic nodes are grouping only. An exercise without a local file is indexed
  only when its public, normalized description is non-empty; serve a generated
  plain-text metadata page for that node. Never index coach-only/private text.
- Node IDs are opaque strings and are always mapped to a deterministic
  positive 63-bit canonical row id derived from `(channel_id, node_id)`. Keep a
  reverse mapping in the producer and fail the build clearly if two distinct
  nodes produce the same row id; never silently merge their documents.
- `EntryRecord.title` = node title; `path` = synthetic stable path
  `node/<node_id>`; `target_id = None`.
- Text contributions, in order:
  1. public node description;
  2. document text (HTML/PDF/plain) when the file is a readable document;
  3. caption text when `captions = "index"` and a caption/subtitle track
     exists;
  4. OCR text when `ocr` is enabled and the item is an image or an image-only
     page;
  5. ASR text when `asr` is enabled and the item is audio/video, unless
     enabled caption parsing already produced usable text.
- Apply phase 04's independent short excerpt and bounded lexical body limits
  to the combined contributions; neither field is limited to descriptions alone.
- By default, do not decode video/audio/image bytes for indexing. Only an
  explicitly enabled derived-text operation may read those bytes, under the
  phase-04 budgets.
- HTML5 apps: index their entry HTML/description, not every bundled asset.
- Fingerprint the selected channel's relevant metadata, node visibility,
  membership, file mappings, and enabled derived-text inputs from a consistent
  installed-DB snapshot, including committed WAL changes, plus a bounded
  ordered manifest of selected storage-file signatures and build settings.
  Recheck those same channel-specific inputs against a fresh consistent
  snapshot before publication. Changes to another channel or unrelated user
  activity must not invalidate this source's index. A storage directory's mtime
  or node count alone is insufficient. Apply the phase-04 caveat about
  metadata-preserving writes and publication races.
- `max_caption_bytes` is the global `[derived_text]` setting and bounds
  caption parsing; it is not a per-source Kolibri key. OCR and ASR caps come
  from the same phase-04-owned global settings.

### Captions and derived text (opt-in)

Apply the canonical operation, caching, provenance, worker, cap, and failure
rules from phase 04. This section only describes Kolibri-specific candidate
discovery and mapping.

- `captions = "index"`:
  - discover existing caption/subtitle files associated with video/audio nodes
    (`*.vtt`, `*.srt`, and Kolibri's stored caption files) through the installed
    DB/file mapping, not a recursive storage walk. Also pass eligible media
    containers to the phase-04 embedded-text-track demuxer;
  - parse to plain text with the shared phase-04 caption extractor: strip cue
    numbers, timestamps, and styling; preserve repeated spoken lines within a
    track. Phase 04 deduplicates equivalent whole contributions, not repetition
    within one contribution. Cap by `max_caption_bytes`;
  - malformed tracks are reported as partial enrichment; skip them and keep
    building other items, with a non-zero overall build exit.
- `ocr = "tesseract"`: OCR image nodes and image-only document pages for which
  the native extractor found no text. Cap pages, pixels, and output bytes; never
  OCR a page that already has a text layer.
- `asr = "whisper"`: transcribe audio/video nodes unless enabled caption
  parsing already produced usable text. With captions off, do not read tracks
  to make that decision. Cap media duration and bytes; run through the shared
  phase-04 process pool with its auto-resolved worker budget (1 on a low-memory
  host when one fits). Never transcribe at request time.
- Engines, models, languages, and caps come from the global phase-04
  `[derived_text]` settings. The phase-00 normalized settings envelope exposes
  this already-defined subset to this provider; phase 08 later completes the
  user-facing loader and diagnostics. A missing
  engine or model disables just that operation for the source with a clear
  health error.
- No network access: models must be provisioned locally before the build.

## Content store

`KolibriContentStore` maps a synthetic path to a local file or HTML5 entry.
The source-level `key` is the URL root; node identifiers are deliberately
named separately:

- Node paths uniquely identify items; content serving does not require an
  index.
- `node/<node_id>` — a document/PDF/plain file, generated public exercise
  metadata, or media file. For HTML5, redirect to its actual entry path under
  `node/<node_id>/` so relative URLs resolve against the entry's directory.
- `node/<node_id>/<relative asset path>` — assets inside an HTML5 app.
- `channel/<channel_id>/<file>` — only a validated channel thumbnail if a
  path is needed; never an arbitrary storage filename.
- Paths are opaque and stable. Never expose the storage path.
- Validate node IDs or encode them as reversible URL-safe single components;
  use the same mapping for results, membership checks, and asset requests.
  Never treat a raw node ID containing separators as a filesystem path.
- Resolve each local file through its DB mapping to the checksum-addressed
  storage layout. Validate the entire checksum/extension filename against the
  supported release's format before opening it, and enforce root confinement.

Handling:

- Documents/PDF/text: serve inline with the correct MIME.
- Video/audio: serve inline with byte ranges (phase 03); do not load the whole
  file for a range request.
- HTML5 apps:
  - support Kolibri's `html5_zip` preset, whose entry is `index.html` at the
    zip root ([format specification](https://github.com/learningequality/ricecooker/blob/develop/docs/htmlapps.md));
    support extracted directories only where a tested release actually uses
    them;
  - other presets such as H5P/IMSCP can require Kolibri-specific viewers; mark
    unsupported formats explicitly instead of treating every zip as an app;
  - serve relative assets under the same source key;
  - apply the phase-05 web-asset MIME policy and never traverse outside the
    app's extracted directory or zip.
- Missing local files: `ArticleNotFoundError` for reads; mark the node
  unavailable during discovery. Do not return a different node's bytes.
- Validate node membership in the selected topic, ungrouped set, or whole
  channel on every content request. A valid node ID from another source must
  not bypass that scope.
- Resolve membership and file mappings from the runtime's pinned entry-level
  snapshot, including nodes outside the indexed manifest. Reload atomically
  replaces that snapshot; in-flight readers retain the old one until finished.
  Do not copy the whole installation DB per channel or per asset request.
- External/on-device resources: only local files are served; external URLs are
  not proxied. Untrusted app HTML may still ask the user's browser to contact
  external URLs; explain the secure-browsing and offline implications.
- Range and size limits follow phase 03.
- HTML is rendered through the existing content shell and secure browsing
  switch.

#### HTML5 zip limits

Enforce these per configured Kolibri entry before shipping this provider, not
only at the phase-09 release gate. The configuration defaults above bound the
number of members, central-directory bytes, individual uncompressed member
bytes, total declared uncompressed bytes, and per-operation wall time.

- Validate the end record, offsets, central-directory size and member count
  before using an API that allocates the complete member list. Reject malformed,
  unsupported or encrypted archives, out-of-bounds/overlapping structures,
  excessive declared sizes, and values exceeding those limits.
- Validate every normalized member path before publishing the manifest; reject
  absolute or parent paths, encoded separators, NULs, links, special files, and
  duplicate normalized names. Ordinary directory entries are allowed. Do not
  extract into a shared filesystem namespace.
- Stream only the requested member in bounded chunks. The per-member limit
  applies to compressed input as well as actual decompressed bytes; abort on
  the time limit or a detected declared/actual size mismatch. HTTP
  response/range caps from phase 03 still apply independently.
- A stored member may support direct ranges. Treat a compressed member as
  non-seekable for phase-03 resource limits: a range may decompress the full
  member only when it fits `max_article_bytes` as well as the zip limits;
  otherwise return the existing too-large error. Do not decompress an
  oversized prefix to satisfy a small range.

### Random

- Prefer the indexed manifest (searchable nodes), then a bounded random sample
  of locally available leaf nodes. Never scan the entire storage tree per
  request.

## Build and reload behavior

- Wire `zimantic build` to configured Kolibri sources in this phase using the
  phase-04 `BuildableRuntime.entry_producer` capability and generic pipeline;
  phase 08 adds the full selection/inspection CLI. Providers do not own a
  separate build/publish orchestration.
- `reload` re-reads installed channel/source metadata and picks up new indexes.
- Adding/removing a channel changes the collection set and clears the relevant
  source caches.
- Kolibri is expected to mutate its database outside Zimantic; the provider
  must handle a concurrently changing DB by opening read-only, catching
  "database is locked"/"schema changed" errors, and retrying discovery on the
  next reload rather than serving stale partial data forever.

## Tests

Build a fixture Kolibri root:

```
kolibri/db.sqlite3
kolibri/content/storage/<checksum[0]>/<checksum[1]>/<checksum>.<extension>
```

Generate the main database from the pinned Kolibri release and imported
channels, not just from an exported channel DB. Include:

- two channels, one with topics and leaves, one with only leaves;
- video/audio with and without `.vtt`/`.srt`;
- PDF, HTML document, a realistic `html5_zip` app, and extracted apps only if a
  supported Kolibri release uses them;
- missing file, duplicate/orphan node, external-only node, coach-only node,
  installed/uninstalled availability differences, and an unknown schema;
- a channel with more topics than `max_sources`.

Assertions:

- [ ] Channel = collection; top-level topics = sources; leaves = items.
- [ ] `granularity = "collection"` yields one source per channel.
- [ ] `max_sources` collapse produces one source and logs once.
- [ ] A whole-channel `:root` override does not opt in the distinct
      `:collapsed` source.
- [ ] Topics never become result rows; a no-file exercise with a public
      description gets a readable metadata page. Coach-only text is excluded.
- [ ] Deterministic node-id mapping is stable across builds and a forced
      63-bit collision fails clearly instead of merging documents.
- [ ] Captions absent by default; present and parsed with `captions = "index"`;
      standalone and embedded text tracks are supported, malformed files are
      skipped, and intentional repeated lines survive. OCR/ASR are never invoked
      unless enabled.
- [ ] A term beyond the short embedding excerpt is searchable, and body
      truncation is reported separately from the source item cap.
- [ ] Missing local files do not break the build or serve another node's bytes.
- [ ] An empty, readable source remains available; an individual missing
      file affects that item without disabling other items in its source.
- [ ] Missing or stale channel export DBs do not change installed discovery;
      mismatched channel/root mappings, malicious storage filenames, and
      arbitrary thumbnail requests cannot expose another channel's data.
- [ ] HTML5 zip entry pages and nested pages serve relative CSS/JS assets;
      unsupported presets are reported; zip traversal, duplicate normalized
      names, symlinks, decompression bombs, and requests for nodes outside the
      source fail within explicit limits.
- [ ] Oversized central directories, member counts, declared/actual output,
      and timed-out reads fail within the zip budgets. A range into an oversized
      compressed member returns the too-large error without decompressing its
      prefix; a valid stored-member range respects the response cap.
- [ ] Video/audio range requests return correct bytes.
- [ ] Discovery, build, search, and serving do not modify the installed DB or
      its WAL/SHM sidecars; committed WAL changes are not silently missed. Test
      unchanged source files with an idle writer and attribute mutations to the
      correct process during concurrent writes. A writer starting during the
      closed-database lease causes prompt release and discards the copy.
      Unindexed nodes remain servable after discovery returns, and reload
      retires the shared snapshot only after active readers finish.
- [ ] Snapshot size, retained-disk, concurrency, and time caps fail safely
      without evicting active snapshots; another process's live snapshot is not
      cleaned up. A failed refresh retains the last complete batch and reports
      its diagnostic.
- [ ] Another channel or unrelated user-table update does not make an otherwise
      unchanged channel index stale; a relevant node/file/availability change does.
- [ ] Unsupported schema disables the collection with an error, not a crash.
- [ ] Concurrent Kolibri writes do not crash Zimantic; reload recovers.
- [ ] No network access; no absolute paths in payloads.

## Acceptance criteria

- An IIAB-style `/library/kolibri` installation appears as one collection per
  channel, with sources for top-level topics.
- Titles/descriptions and readable documents are searchable, including media
  node metadata. Media bodies contribute text only through the independent
  opt-ins `captions`, `ocr`, and `asr`.
- The provider never writes to Kolibri, and generates no derived text unless
  that operation is explicitly enabled.
- `python -m pytest` passes, including a fixture DB that needs no Kolibri
  installation.

## Risks and mitigations

- **Schema drift.** Isolate all SQL/schema knowledge in `schema.py`, detect
  versions, and fail closed with a clear message.
- **Zipped HTML5 apps.** Resolve inside the archive/manifest only; zip-slip
  tests are mandatory.
- **Large channels.** Bound source count, node scan, caption size, OCR pages,
  ASR duration, and preview reads; mark truncation.
- **Protected/private content.** Do not surface coach-only or unavailable
  content; follow the database's availability flags and document the rule.
- **Concurrent writes.** Bounded, supervised snapshots may briefly delay a
  writer; abort on a lease break and retry on the next reload. Unsupported
  safety or timing guarantees fail closed.
