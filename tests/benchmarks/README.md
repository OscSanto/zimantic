# Mixed-library benchmark

`run_mixed.py` measures the mixed-library fixture generated by
`tests/fixtures/mixed_library/generate.py`.

```bash
python tests/fixtures/mixed_library/generate.py --root /tmp/zimantic-mixed --force
python tests/fixtures/mixed_library/kiwix_server.py --port 8085 &
python tests/benchmarks/run_mixed.py --root /tmp/zimantic-mixed \
    --build full \
    --device-model "Raspberry Pi 4 Model B 4 GB" --ram 4GB \
    --os "Raspberry Pi OS 64-bit" --storage "USB SSD" \
    --commit "$(git rev-parse --short HEAD)" \
    --fixture-revision phase09-v1 \
    --json-out tests/benchmarks/results/pi4-phase09.json \
    --markdown-out tests/benchmarks/results/pi4-phase09.md
```

The report contains:

- startup time until `/health` is ready with local Kiwix available;
- cold and warm build times for the 1,000-file tree and Kolibri channel (run
  `--build` twice);
- search p50/p95 after one warm-up request over the fixed 100-query set;
- `/library` payload size and render time;
- peak process RSS (`VmHWM`) after the server handles search requests;
- a ZIM-only and mixed-library `/search` comparison using the same query file.

The benchmark measures ZIM, Files, and Kolibri providers together. It requires
the documented fixture and query set. Store results in
`tests/benchmarks/results/`. A missing Raspberry Pi 4 result is unverified.

`scripts/benchmark_body_fts.py` provides a synthetic comparison. It does not
replace a measurement with the real providers.

## HTML parsing

`run_html.py` compares the stdlib streaming parser, the production Lexbor
extractor, lxml's streaming target and DOM, and Beautiful Soup + lxml. Each
parser uses the same text-selection rules. Comparison-only dependencies are
not application requirements:

```sh
uv run --with lxml --with beautifulsoup4 python tests/benchmarks/run_html.py \
    --zim zims/wikipedia_en_100_2026-08.zim --module modules/en-olpc \
    --pages 12 --repeats 5 --output /tmp/zimantic-html
```

The output includes repeated body and preview timings, exact-output agreement,
empty-result regressions, fresh-process native-memory probes, and blinded
review samples with source HTML. Record preferences before
opening `review-key.json`. Archive decompression and file I/O are excluded.

See [the November 7 results](results/html-parsers-2026-11-07.json) and
[quality/memory caveats](../../docs/build-performance.md#html-parser-comparison-november-7-2026).
