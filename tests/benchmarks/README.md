# Release benchmarks

`run_mixed.py` runs the phase-09 mixed-library gate against the fixture
generated by `tests/fixtures/mixed_library/generate.py`.

```bash
python tests/fixtures/mixed_library/generate.py --root /tmp/zimantic-mixed --force
python tests/fixtures/mixed_library/kiwix_server.py --port 8085 &
python tests/benchmarks/run_mixed.py --root /tmp/zimantic-mixed \
    --build full \
    --device-model "Raspberry Pi 4 Model B 4 GB" --ram 4GB \
    --os "Raspberry Pi OS 64-bit" --storage "USB SSD" \
    --commit "$(git rev-parse --short HEAD)" \
    --fixture-revision phase09-v1 \
    --json-out tests/benchmarks/results/pi4-phase09.json \
    --markdown-out tests/benchmarks/results/pi4-phase09.md
```

Measured fields:

- cold startup to an HTTP-ready `/health` with Kiwix available locally;
- cold and warm build time for the 1,000-file tree and fixture Kolibri channel
  (run `--build` twice and record both);
- search p50/p95 after one warm-up over the fixed 100-query set;
- `/library` payload bytes and render time;
- peak process RSS (`VmHWM`) after serving and searching the fixture;
- the ZIM-only versus mixed `/search` comparison (run with a config containing
  only the ZIM collection and compare the same query file).

The benchmark records ZIM, Files, and Kolibri providers together.  A result
from a synthetic corpus or a different query set does not satisfy the release
gate.  Store recorded results under `tests/benchmarks/results/`; a missing
result is unverified, not a pass.

The phase-04 `scripts/benchmark_body_fts.py` comparison remains a useful
synthetic probe, but it does not replace this real-provider measurement.
