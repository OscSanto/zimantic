# API reference

## JSON API

The JSON API provides these endpoints.

- `GET /search?q=...&limit=10&offset=0&source=<key>&collection=<key>` returns one page of results.
  - `source` is the only source-scope parameter. Repeat it to select individual sources. `collection` selects one collection as a unit. When both are present, the scope is their intersection.
  - After an unscoped search, the UI keeps the discovered source chips and their broad-search counts in browser memory for the same query. Selected sources get counts from their deeper search. Reloading or changing the query discards that discovery information.
  - An explicit selection defines the scope directly. There is no promotion to a full search and no `zim` parameter. Unknown source or collection keys return HTTP 400. A valid selection with no eligible sources searches no sources rather than broadening to the library.
  - An unscoped remote fan-out cap does not drop an explicit individual source. An explicit Kiwix collection is capped at `max_explicit_collection_sources` (500 by default) and by `search_timeout_seconds`; partial work appears in `X-Search-Scope`.
  - Totals appear in the `X-Total-Count`, `X-Has-More`, `X-Offset`, `X-Page`, and `X-Page-Count` headers. `X-Search-Scope` carries the JSON scope summary. An offset past the last page is clamped to the last real page, and `X-Offset`, `X-Page`, and the stream's `offset` and `page` report that effective position.
  - Kolibri results include optional `breadcrumbs` (channel, ancestor topic titles, resource title) and a `resource` object in both search endpoints. Resource fields are `kind`, `description`, `author`, `language`, `grade_levels`, `duration` (seconds), `tags`, `learning_activities`, `assessment_count`, `topic_position`, and `topic_total`. Position is one-based tree order among available, non-coach resources directly inside the same topic, not an authored lesson number; topic folders are excluded. Metadata comes from the pinned content snapshot, never learner records or per-result HTTP requests, and is omitted when unavailable.
- `GET /search/stream?q=...&limit=10&offset=0&source=<key>&collection=<key>` returns newline-delimited progress events and result snapshots.
  - `snapshot` and `done` events carry the effective `page` and `page_count`. The terminal `done` event carries the same `scope` object as `X-Search-Scope`.
  - The scope object reports `requested`, `scheduled`, and `completed` source tasks plus a `status` of `complete` or `partial` and a `limit_reason` of `source_cap`, `deadline`, or `null`. A per-source provider error stays in that source's result and does not imply a scheduler cap.
  - While sources run, the stream emits a `progress` heartbeat about every 700 ms. When a source finishes between heartbeats, the stream emits a snapshot.
  - A source that finishes between ranking passes reports no count until the next snapshot. The final `done` event always carries the complete per-source count map.
  - A cached search replays `started`, the cached source events, and one `done` event with its final page. It does not send a duplicate `snapshot`.
- `GET /suggest?q=...&source=<key>&collection=<key>&limit=8` returns title-completion candidates for the selected sources or collection.
  - Suggestions use titles only: no embedding, no full-text search, and no article reads. A typing pause is cheap to answer.
  - The response is a plain list of result objects. Sources without a Zimantic title index contribute nothing. Submitting the query without a suggestion opens `/?q=...&source=...` or `/?q=...&collection=...` for a full search.
- `GET /content/<source-key>/<path>` serves a toolbar shell for a local source entry. `GET /content/<source-key>` serves the resolved source homepage.
  - The shell keeps the navigation bar in the page and loads the article from an inner iframe pointed at `/article/<source-key>/<path>`. The toolbar stays visible when the article is missing or fails.
  - Unreadable entries render an error panel in the shell, not the raw `/article` JSON error body.
  - Non-inline attachments render a download panel, not an empty iframe that the browser abandons.
  - `GET /article/<source-key>/<path>` serves the raw entry. Redirects are followed, its assets resolve under the same route, and entries larger than `max_article_bytes` return `413`.
  - `/article` supports one inclusive byte range per request (`bytes=start-end`, `bytes=start-`, or `bytes=-suffix`) and returns `206` with `Content-Range`, or `416` when the range starts past the representation. Unknown or malformed ranges, multiple ranges, and `If-Range` without a validator return the bounded full response. Raw HTML is bridge-decorated and ignores ranges.
  - A missing or ambiguous entry, an unknown source key, or a source with no content store returns a JSON error envelope with a stable `error` code and the public `source` key. A store that cannot be opened returns `503`. `/article` includes `Access-Control-Allow-Origin: *` on success, redirects, partial and unsatisfiable responses, and errors. Its bounded `OPTIONS` preflight allows `GET`, `HEAD`, `Range`, `If-Range`, `If-None-Match`, and `If-Modified-Since` without credentials.
  - With scripting enabled, opening `/article/` as a top-level page hands off to the matching `/content/` shell. Without scripting, or when the entry is fetched, it stays the raw entry. `/article/` stays the entry source for the iframe, assets, and offline fetches.
  - The article bridge filters out clicks that the browser must keep (in-page fragments, modified clicks, downloads, non-HTTP(S) schemes, and links with a non-self target such as `_blank`, which open in a new tab). It reports the authored `href` plus any `<base>` to the shell.
  - The shell resolves that `href` against the article's local `/article/` URL and decides whether to handle it offline, in the app, or externally. It hands same-origin app links to the outer page when the shell is embedded in the modal. This keeps replay shims such as zimit's `wombat.js` from turning relative links in the capture into live-site URLs.
  - `max_html_bytes` limits how much HTML is parsed for indexing and phrase checks, and caps preview scans. Previews use a smaller fixed prefix (32 KiB) so one large page cannot dominate latency. `max_article_bytes` limits the uncompressed response body because Zimantic reads each requested entry into memory, including binary assets.
  - The toolbar shell uses the viewed article's `<title>` and declared icon for the browser tab title and favicon, with the ZIM's source icon as the fallback. When the shell is embedded in the modal, the outer page mirrors them and restores its own title and favicon when the modal closes.
  - HTML and XHTML articles include a small navigation bar with Close, Home, Random, Permalink, a Zimantic library search control, and a ZIM-scoped search box. The scoped box is hidden on phones and when the ZIM does not resolve to an available local source. Alt-clicking Random opens the homepage of a random available ZIM.
  - Modal articles also expose icon-only navigation through the visible search results and, for nested articles, the adjacent article links listed on the article's parent page. When a modal article opens another modal article, the preceding article can also provide the navigation context.
  - Back navigation uses browser history when available; otherwise the Close control tries to close the tab. In a directly loaded `/content/` view, Close closes the tab or window when the browser allows it; otherwise it goes back through history, or opens the library when the article is the first history entry.
  - Article views keep the viewed ZIM and path in the address bar, including from `/library`, so the URL can be shared.
  - Selecting text adds the passage to that URL and to the toolbar's Copy link action. Reopening the link scrolls to and highlights the passage. Fragment links scroll inside the article without reloading the shell.
  - With `secure_browsing = true`, the article iframe has an opaque origin. Articles that use Web Storage get an in-memory fallback, and IndexedDB loads an in-memory polyfill. The shell offers the standalone `/content/` view only when secure browsing is off, because a sandboxed standalone view cannot provide persistent storage.
  - The IndexedDB polyfill bundles `fake-indexeddb` (Apache-2.0; see `indexeddb-shim.LICENSE`).
  - Stack Exchange captures that omit their MathJax font files are served the vendored MathJax 2.7.5 WOFF set. Root-absolute capture assets such as `/w/images/...` resolve through the article referrer against the common archived locations (`-/mw/...` and similar) when no app route matches.
  - `GET /random?source=<key>` redirects to a random article's shell for that source. `GET /random` without `source` redirects to the homepage of a random available local source, including Files and Kolibri sources. The article toolbar's Random control uses the first form; Alt-clicking it uses the second.
  - Links from an offline article to an external `http` or `https` site show an in-modal notice that identifies the destination as online and offers to open it in a new tab. This avoids failures from sites that disallow iframe embedding. A directly loaded `/content/` view tries the captured copy for same-site links before it leaves for the live site, so only links missing from the ZIM go online.
- `GET /sources`, `GET /library.json`, `GET /collections.json`, `GET /config`, and `GET /health` return source, library, collection, configuration, and health information.
  - `/sources` describes searchable sources and carries the canonical `key`, `provider`, `title`, `collection`, `searchable`, `homepage`, `icon_url`, `size`, `intent_phrases`, `media_types`, `item_count`, `indexed_count`, `truncated`, `body_truncated_count`, `index_freshness`, and `derived_text` fields. It never exposes a filesystem locator or an `available`/`error` status.
  - `/library.json` describes library sources from every provider, including external-only Kiwix books and unsearchable archives. Its records have the same canonical shape. Metadata includes `provider_id`, `mime_counts`, and `native_fulltext_available`.
  - `/collections.json` returns collection records with `key`, `provider`, `label`, `title`, `description`, `source_count`, `media_types`, `error`, `discovery_state`, `snapshot_version`, `last_refresh`, `collapsed`, `index_count`, `index_states`, `indexed_count`, `truncated`, `body_truncated_count`, and `icon_url`. `source_count` counts all discovered library sources. `/health` exposes the searchable subset and the same per-collection observability fields.
  - All three listings accept optional `provider`, `media_type`, and `q` filters. `/sources` and `/library.json` also accept an exact `collection` key. `q` is a case-insensitive substring match on approved display fields (title, label, description, provider, and collection metadata), not a content search. Unknown enum values and collection keys return HTTP 400. Filters compose before paging and `X-Total-Count` describes the filtered snapshot.
  - Listings capture one discovery snapshot token with their records. Responsive pages, `304` responses, and filtered responses carry `X-Total-Count`, `X-Offset`, `X-Has-More`, and `X-Snapshot-Version`. A client that sees the version change while paging reloads rather than mixing revisions. An omitted `limit` uses the global `page_size`. Explicit limits are positive and at most 200 for `/sources` and `/collections.json`, or 1000 for `/library.json`.
  - `/config` exposes `source_filter_limit`, `collection_source_limit`, `max_explicit_collection_sources`, and the configured provider kinds.
  - Failures are operation-scoped: a search result carries its source error, and a content request reports its own failure. Listing does not probe sources and does not persist availability or last-error state.
  - `/health` is read-only and reports index and archive capabilities, per-collection source/searchable counters, entry counts, homepage resolution, embedding state, and search and preview cache statistics.

To include ranking scores and explanations in both search endpoints, start the server with `zimantic serve --debug` (or its alias, `serve --dev`).

- Debug result objects include a `ranking` breakdown with each semantic, title, and full-text rank and contribution, title-match signals, intent, and disambiguation adjustments.
- Stream `snapshot` and `done` events always carry source progress and a per-source result count. In debug mode they also add `matched_by` match-method counts.
- The non-streaming endpoint exposes match counts in the `X-Matched-By` header, and the web UI renders them above the results.
- Debug output is configured for the whole server, not per request. `SIGHUP` restarts the whole server in debug mode.

Reloading indexes is not an HTTP API. A running server rescans with `zimantic reload` or `kill -HUP <pid>`.
